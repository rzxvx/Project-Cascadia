# P105 parent transport and complete ADC6 software owner

This is an uninstalled source candidate based on Cascadia `3cf90cafbc295e87d1ff7a1436efc8667201be51`. It connects the actual parent bank0 transport and existing ADC6 poll implementation. Neither Kconfig nor DTS, normal builds, firmware stages, iPad state or host services were changed. Both experimental options and runtime parameters default off. The real first ADC conversion remains denied (`-EUCLEAN`, no PMU I/O); no runtime API creates an initial physical quiescence witness. Successful tests deliberately set that premise in fake RAM. Each begin consumes an epoch-bound witness once; even a successful checked conversion/cleanup does not recreate it. Every subsequent conversion requires a new independently qualified physical witness, for which no runtime producer is installed.

## Implemented transport and ownership

`apple-pmu-d1946-bank0.c` uses the same parent mutex and adapter segment lock for all normal GPIO, regulator, WLED and checked poweroff preparation operations. The private ADC backend retains both locks across initial control read, start, every poll/wait, result read and checked cleanup. Its unassociated lockless regmap facade calls the actual parent selector/data transactions. It is not registered on the parent device or returned to normal children. Linux's `disable_locking` branch also disables this map's debugfs. Normal children retain `pmu->regmap`.

The actual A5 driver has a client-bound PMU reservation under its existing adapter lock. Generic `master_xfer` and `master_xfer_atomic` reject **any** message addressed to `0x3c` while this reservation exists, including mixed-message requests; supported 7-bit messages to other devices retain the existing path. During reservation, all messages are validated before the first transfer: unsupported high addresses and TEN flags are rejected. The actual unchanged A5 start-write body emits exactly the same FIFO command178 for addr3c and addrbc; Linux I2C_RDWR does not reject that unsupported address itself. The previous exact-address-only filter fails the new alias regression; the captured historical result proves why the supported-address guard is required. Only the typed parent entry may access that address. It checks the actual private algorithm identity, client identity, adapter suspension, exact supported message shape and atomic context, then invokes the unchanged existing `do_xfer` once. The sleeping path takes the original A5 private mutex; the poweroff path has the existing late/IRQ-off restriction. No adapter proxy or global retries/timeout change occurs. The helper does not promise generic I2C tracepoints or arbitrary adapter/quirk support.

This removes the previous dependency on an immutable retries0 contract: Linux6.12 `i2c-dev.c` writes `adapter->retries` without the adapter lock; `__i2c_transfer()` reads it again during its `-EAGAIN` loop. A check before calling that core function cannot enforce one attempt. The actual core function in the C fixture changes initial retries0 to2 during the first fake transfer and executes twice. The typed A5 path executes once, returns the first synthetic `-EAGAIN`, and latches uncertainty. The currently inspected A5 transfer bodies produce EINVAL/EIO/ENXIO/ETIMEDOUT rather than EAGAIN; this control proves generic core retry behavior under an explicit fake errno, not a demonstrated current A5 hardware replay. The immediately concrete improvement is that changing the mutable global retries value no longer makes this supported single-attempt transport reject existing parent operations with EOPNOTSUPP. `I2C_TIMEOUT` is likewise mutable; the typed existing A5 transfer bodies use their own compiled polling bounds and do not read it. Other adapter users still follow ordinary core policy. No claim that the adapter lock enforces global configuration immutability is made.

The ALL-ADC software claim permanently reserves the parent data/control window `0x43..0x45` for this owner. Its facade permits only ADC6 control `43=26/00`, control reads and the two-byte `44` result. It does not read events `01..09`, register an IRQ owner, replay initialization tables, expand the separate experimental charger register allowlist, or grant any charging/source/analog permission. The shared parent still supports its independently evidenced normal registers.

## Lifetime and errors

The full private MFD constructor immediately registers rollback-stop after reserving the bus, before parent regmap construction can fail. A second idempotent stop is registered after that map so existing child/GPIO/sys-off consumers drain before transport stop and map destruction. The first stop which owns the reservation releases it once; the earlier rollback then observes it already released. The ADC close action runs before facade exit, backend storage destruction and parent stop. Close invalidates before waiting for the admitted complete conversion. The actual owned MFD system-sleep/freeze/poweroff callbacks close the owner without an automatic resume validity grant; actual poweroff preparation closes/drains before the existing PMU preparation and seal. CONFIG_SUSPEND remains off in the normal build; callbacks are independently compiled/tested as an uninstalled candidate. Parent stop sets STOPPED before drain, so a concurrent conversion's later selector/data calls fail and output is cleared; cleanup may then remain physically unknown. A checked release error is retained rather than pretending the controller is unreserved. On release failure the controller can retain a client identity value after parent context destruction; it does not dereference that value, generic PMU access remains blocked, and no new owner may claim it. Driver/provider structural lifetime must remain valid through stop; devres drain does not justify calling a destroyed provider. No automatic reservation repair or success reset is implemented.

Both the facade and parent use actual Linux regmap interfaces. Fakes substitute low-level register memory, clock/wait, devres storage, pthread locks and A5 MMIO transport. Current C bodies for `regmap_read/write/update_bits`, `__i2c_transfer`, A5 wrappers and the MFD constructor are pinned or compared against source. Tests cover all selector/data transport failures and shorts, epochs, wrap, timeout, concurrent normal/raw users, close/stop, actual unchanged GPIO/regulator/WLED/poweroff, mixed raw messages, suspended/atomic rejection, constructor allocation/map/action failures and 84 original parent-oracle cases. The original retry race and earlier missing probe rollback have historical controls. An earlier attached-facade constructor fails the new registration regression, as captured separately. The earlier raw filter also fails the actual FIFO alias regression.

Framework consumers must stop issuing new calls before devres destroys an opaque ADC handle or regmap. A drain is not a reference-count fence for escaped arbitrary handles. This draft exports no independent registered consumer or external worker. Future consumers require actual managed lifetime/teardown integration. Lock order is backend serial -> parent map mutex -> adapter segment lock -> existing A5 transfer mutex; the poll's own mutex is internal while those locks are retained. No PMU I2C runs under a spinlock. Atomic poweroff uses adapter trylock and fails instead of interrupting a conversion. Conversion deadline checks are software policy, not measured physical duration; underlying checked transport and cleanup can add time.

## Exact unresolved physical boundary

The pinned 12H321 callback at `0x80ecbe2c` accepts state1, changes it to2 and wakes the gate without a conversion token or control-channel check. The actual acquisition at `0x80ecd9c8` ignores start and cleanup write errors; after returning it resets software state0. The IRQ path `0x80ecbca4` reads all nine event bytes through `0x80ecc460`; event02 bit20 routes that callback. This draft does not imitate that read-to-clear consumer. Read43=0, a software timeout, event arrival or a successful cleanup write is not independently a physical no-late-completion proof.

`check-quiescence-private.py` executes two actual acquisitions in one fake owner: first timeout plus failed cleanup leaves control2f despite software0; second failed channel6 start plus deliberately injected old completion/raw111 returns raw111 as success. The result proves missing software distinction under those **explicit synthetic premises**, not that real hardware produces that ordering. It justifies keeping first admission closed until an actual ADC reset/cancel/completion ordering or a qualified boot handoff and persistent sole owner is proved. It does not imply CV, termination, thermistor calibration or autonomous fault protection, and none of those assumptions is enabled.

## Reproduce and export

Run `python3 test-owned-adc.py` in this directory; set `CASCADIA_TEST_SOURCE_ROOT` to a matching Cascadia checkout to additionally compare whole unchanged child sources and actual current Linux bodies. Host GCC, pthreads and ASan/UBSan are required, no Apple image for the 15 C groups/84 oracle cases. `source-provenance.json` hashes are actually asserted by the runner.

The original-quiescence check is separate and optional: execute `check-quiescence-private.py SOURCE_ROOT KERNELCACHE12` with Unicorn installed in the existing offline build image; it verifies the pinned image and records explicit premises. `check-historical-registration.py` compiles the captured historical own GPL C and expects the new default regression to fail. These checks use no hardware.

`reproduce-arm.sh` uses the existing restricted offline Docker wrapper, the separate prepared Linux6.12 tree and private stage only. It compiles five enabled objects with actual ARMv7 headers plus separate normal-default-off and PM_SLEEP callback-API MFD objects; it does not build/install/boot a kernel. Sources, patch order, hashes and logs are in the export manifest. Install nothing automatically. This is an alternative experimental package; normal overlays/config and the existing standalone parent/ADC experimental packages remain untouched.
