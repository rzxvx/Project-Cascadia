# D1946 ADC identities and scaling: offline evidence

The p105 **12H321** firmware exposes two separate channels named `vbus` and
`vbus_b`, plus a channel named `chg_temp`. These are measurement identities;
they do not establish a 5 V output supply, boost regulator, USB host permission
or safe charging configuration.

Source: official iPad2,5 iOS 8.4.1 kernelcache, SHA256
`db1ddc8343aa9debc00e0a083fba59d9f555722db60957dc333b854fac21dd2c`.
See [firmware provenance](p105-charging.md). Fixed addresses apply only to
that image. No Apple executable bytes are distributed in this harness.

## Actual software identities

The bounded experiment executes D1946 metadata mapper **0x80ecdd8c**, with
only its imported `strlcpy` operation mocked. It performs no PMU transaction.

| Channel | Firmware name | Three metadata bytes |
| --- | --- | --- |
| 0 | `vcc_main` | `Vc0` |
| 4 | `vbat` | `VB0` |
| 15 | `vbus` | `Vu0` |
| 27 | `vbus_b` | `Vu1` |
| 21 | `chg_temp` | `Tg0` |
| 18 | `buck5_temp` | `Tb5` |
| 19 | `ldo9_temp` | `Tl9` |
| 20 | `cbuck_b_temp` | `Tcb` |
| 22 | `buck0_temp` | `Tb0` |
| 23 | `buck2_temp` | `Tb2` |
| 24 | `buck3_temp` | `Tb3` |
| 25 | `buck4_temp` | `Tb4` |
| 26 | `cbuck_a_temp` | `Tca` |

The metadata bytes are reported literally. Their voltage/temperature naming
is consistent with the mapper, but physical pin mapping and calibration are
not certified. In particular, `chg_temp` must not be substituted for the
battery temperature reported by its separate fuel gauge.

## Actual scaling with blocked raw conversions

The voltage scaler **0x80ece490** and temperature scaler **0x80ece328**
execute their actual instructions, including integer division. The raw ADC
callback at PMU vptr +0x3ac is replaced by a synthetic sample/error provider;
**the real conversion/start routine never executes**.

For bounded raw samples 0..4095, the observed integer transformations are:

| Channels | Stored scaled integer |
| --- | --- |
| 15, 27 | `88 * raw` |
| 0, 4 | `163840 + 32 * raw` |
| 21 | `26 * 65536 + trunc_zero((23662 - 10 * raw) * 17290 * 65536 / 1000000)` |

For channels 15/27, the inspected multiplier is 88000 followed by division
by 1000. For 0/4 it is `(0x09c40000 + raw * 32000) / 1000`.
The temperature transformation uses literals 0x438a0000 and 1000000;
truncation is toward zero, including negative samples. Firmware temperature
logging shifts its result right by 16. These are fixed-point software values,
not host sysfs units, measured voltages or proof of accuracy on our hardware.

Raw-provider errors propagate through the tested scalers and leave the output
sentinel untouched. This differs from the unchecked status-read behavior in
[the charging status getter](p105-charge-status.md). A future driver must keep
these error paths distinct.

## ADC acquisition has side effects

Manual inspection of actual raw ADC routine **0x80ecd9c8** shows that the
normal path writes **register 0x43** with its selected channel and start/mode
bits, updates software state +0x94, and waits through the command gate and
interrupt lifecycle. Successful conversion reads **0x44/0x45** and reconstructs
`raw = (byte0 & 0x0f) | (byte1 << 4)` at 0x80ecdb74..0x80ecdb9a.
This is a 12-bit result. Channels 5/9 have an additional error path when the
first byte's sign bit is set. Afterwards the routine writes control 0x43
again and wakes waiting users. The complete IRQ path is not emulated here.

A separate diagnostic/BIST path invokes **0x80ecdc24**. It writes logical
register **0x15d**, delays, checks status there and reads **0x15e/0x15f**.
These wider logical addresses must not be silently truncated into the
existing 8-bit Linux regmap. The normal conversion and BIST sequences are
**not passive reads** and are outside the current device authorization.
The harness mocks raw conversions instead of copying these sequences.

## Tests and remaining work

```sh
python3 tools/power/emulate-d1946-adc.py build/firmware/kernelcache.12H321.macho
python3 tests/test-d1946-adc-emulation.py
```

Seven actual-code tests pass in the existing offline Cascadia image without
skips: separate channel identities, temperature names, voltage boundaries,
offset preservation, signed temperature arithmetic, provider errors and input
hash/range guards. Tests verify no PMU transactions occur during names or
scaling. They do not validate analog readings, dynamic ADC concurrency,
interrupt clearing, settle time, hardware calibration or physical protection.

Next useful work is to trace the exact ADC completion IRQ and cancellation
policy, identify calibration/property ownership and match acquisition/units
to a Linux IIO interface. Such work must remain separate from charger target
voltage, battery thermal limits and fault shutdown. This evidence enables no
measurement or charging-control callback by default.
