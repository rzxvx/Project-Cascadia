# P105 XNU PMGR / AIC extract (iOS 8.4.1)

Kernel: `kernelcache/kernelcache.p105.raw` (or set `KERNELCACHE=...`)
Size: **16326628** (0xf91fe4) bytes. Mach-O armv7, `__TEXT` @ `0x80001000`,
`__PRELINK_TEXT` @ `0x80460000`.

Generated by `scripts/xnu_pmgr_extract.py`. Kexts are PIC (`ldr` + `add rd, pc`).

## Verdict

**No A9 global-timer stores.** Zero literals for `0x3E100200` / `0x3E100600`.
`_initPMGRState` (`0x80b8d434`–`0x80b8d8a4`) only **reads** PMGR through
`vtable+0x490` (`read32(_pcBaseAddress + off)`). Timebase is **AIC** at phys
`0x3F200000`, counters `+0x6008/+0x600c` (shared, stride 16) or `+0x2048/+0x204c`.

Clock gates: **`0x3F100000 + 0x1000 + id*4`**, not iBoot `0x3F101008 + id*4`
(off-by-8 = two IDs). Poll **does** match iBoot: wait until bits 0–3 equal bits 4–7.

> **Both of those addresses are wrong, measured on hardware 2026-09-18.** The
> array starts ten ids lower: `reg = 0x3f100fd8 + id*4`. SPI1 and the PWM were
> switched on that way from a running Linux, having never budged at either
> address above. See `p105-pmgr-gates.md`; the write recipe and the poll below
> are right, it is only the base that was misread.

## `function-clock_gate`

`AppleS5L8940XIO::start` (`0x80b8b7c8`) looks up that DT function name.
Implementation:

**`clock_gate_switch` @ `0x80b8de38`** `(this, id, enable, nibble)`

```
offset = 0x1000 + id*4
val = (read32(pmgr+offset) & 0xFFFFFEF0) | nibble
write32(pmgr+offset, val)
while ((read32(addr) ^ (read32(addr)>>4)) & 0xF) != 0;
```

Id wrapper @ `0x80b8d154`: ignore `id > 0x57`; poke bit 31 then restore.
`start()` scans ids **9..87**. ADT `clock-gates = {121,122}` still out of range.

## AIC `#shared-timestamps`

Looked up at insn `0x80cb3d62`. Reader **`0x80cb4774`**:

- vector `>>28 > 0xe`: `hi=aic+0x204c`, `lo=aic+0x2048`
- else: `hi=aic+0x600c+(index<<4)`, `lo=aic+0x6008+(index<<4)`

Bring-up writes: `0x5010` (per-cpu `+0x80`), `0x5024=0x80000001`, `0x3000=0`,
`0x4100=~0`, slot enable `aic+(0x6000|index<<4)` bit 31.
